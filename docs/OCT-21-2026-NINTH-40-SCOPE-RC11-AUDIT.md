## Four source-confirmed newly corrected defect groups
1. **N9-01 / Core schema state lies.** Main `MKT_DB::maybe_upgrade` previously trusted `mkt_schema_version` and `mkt_plugin_version` in `wp_options` and returned without checking actual deployed tables/columns. This allows partial DB schema to remain falsely current. New bounded periodic `schema_ready()` checks **all 15 File18 core tables** and necessary critical columns, with a five-minute verification cache to prevent per-hit metadata overload, guarded upgrade recheck, and `mkt_schema_error` on failed repair. New direct fake-DB regression `tests/test-core-schema-truth.php` simulates missing table and missing listing version even when old options say 'current'. **Real DB and its precise migration state still not verified.**
2. **N9-02 / File17-only legacy migration silently skipped.** `MKT_DB::migrate_legacy_foundation` checked only legacy sellers/products before its early exit and stamped migration done. Existing `smp_conversations` and `smp_messages` without those two were never inventoried for File17. Moved chat/message existence checks before early exit; added `tests/test-file17-legacy-only-migration.php` for conversations-only/messages-only and failed handoff write. No duplicated File17 conversation storage.
3. **N9-03 / Composite UNIQUE index falsely accepted.** `MKT_Governance::schema_ready` considered only the first column of each unique index; `UNIQUE(public_id, other)` can allow duplicate `public_id`. Now validates exactly one-column `PRIMARY(id)` and `UNIQUE(public_id)` / `UNIQUE(listing_public_id)`; added composite-index negative case to `test-governance-schema-truth.php`.
4. **N9-04 / Privacy erasure false-complete on SELECT failure.** `MKT_Privacy::erase` could treat a failed report/dispute `get_results` or NULL/SQL-error offer/deal count as no results and return completed/Audit success. Now all those reads are required: incomplete with retention message and `done=false` on failure. Added read-failure cases in `test-privacy-hold-failclosed.php`.

**Additional source-only safety contract:** `tests/test-cf05-conditional-boundary.php` asserts File18 is a versioned domain-event owner and does not create/write CF05 analytic warehouse tables, while File17/19 remain consumer owners. This is not a real CF05 plugin integration test and does not activate conditional CF05 features.
